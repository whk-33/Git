## 0. 数据源说明（**写代码前先确认这一节**）

### 0.1 双轨策略

正式数据源是本校数据，但**建议先用 OULAD 在 1 周内把完整 pipeline 跑通一遍**——原因：OULAD 是公开 benchmark，pipeline 各环节无数据依赖，跑通即可证明图构建、时序聚合、DKT 序列构造等逻辑无误；之后替换为本校数据时只需改数据源适配层（原始表清单、字段映射、已知坑），通用层逻辑不动。

## 1. 这份文档解决什么问题

团队方案里给你阶段一分配了 4 项任务，但只有一句话描述。本指南把每一项拆成「**做什么 → 为什么这么做 → 具体怎么做（含代码）→ 产出什么 → 怎么验收**」，照着执行即可在两周内交付：

1. 本校数据全量探查与清洗（含跨系统 ID 打通、出勤/随堂小测日志标准化）；
2. 异质图 Schema 设计与图数据构建（含 `class_session` 节点、出勤边、同班同侪元路径）；
3. 按周粒度的时序特征提取（出勤率 / PPT 交互 / 随堂小测并入时变特征）；
4. 知识点体系与依赖链映射（**DKT 序列从小题级构造**，利用随堂小测自带的知识点标签）。

**阶段一的所有产出都是阶段二 4 个模型的输入**，请始终带着下游视角工作：

| 下游模型（阶段二/三） | 依赖你阶段一的什么产出 |
|---|---|
| 异质 GNN（HAN） | 异构图文件（节点、边、元路径）、节点特征、同班同侪元路径 |
| DKT 知识点级预警 | **逐题答题序列**（随堂小测）、知识点映射表 |
| TFT + DeepSurv 时序预警 | 静态特征 + **出勤/PPT 交互/随堂小测并入**的时变特征表、标签时间轴 |
| DoWhy 因果推断 | 干净的宽表——**treatment = 出勤达标率**（比图书馆频率干净得多）、混淆变量、结果变量 |
| GNNExplainer（阶段三） | 图 Schema 中节点/边类型语义清晰、ID 稳定、出勤边可解释 |

## 3. 前置准备

### 3.1 必须先建立的几个口径概念（全组统一，后面不再争论）

1. **分析主体是「学生 × 课程开课（学期）」**，不是学生本人。同一脱敏学号可能在多个学期、选多门课，所有表都以"学生+课程开课"粒度聚合。
2. **时间对齐统一用校历表**：业务系统存真实日期，全部换算成"学期第几周、星期几"（用校历表开学日作 week=0）。
3. `final_result` 四类（教务系统口径，OULAD 对齐作参考）：`优秀/良好/合格/不合格/缺考/退学/休学`。**风险标签怎么二值化必须在阶段一和全组确认**（建议见 §4.4）。
4. **数据合规**：学号在出库前由数据提供方替换成不可逆匿名 ID，姓名/手机号/身份证一律不拿；数据存校内服务器或加密环境，不进个人电脑和公开 Git。

## 4. 任务一：全量探查与清洗（T1）

### 4.1 探查（EDA）做什么

对每张表输出并记录以下内容（形成 `docs/数据质量报告.md`）：

1. 行数、列数、字段类型、内存占用；
2. 每列：非空数、缺失率、唯一值数；类别型列出全部取值分布，数值型给出 min/max/均值/分位数；
3. 主键唯一性检查（如考核 ID 是否唯一、同一学生+课次+签到时间是否重复）；
4. 表间引用完整性（见 §4.3 代码）；
5. 明显的越界/逻辑矛盾值（缺勤却有签到时间、迟到分钟为负等）。

### 4.2 本校数据已知质量问题清单（重点）

本校数据的坑和 OULAD 完全不同，**不要照搬 OULAD 的已知清单**：

| 表/来源 | 问题 | 处理规则 |
|---|---|---|
| 跨系统 | **学号/课程代码口径不一致**：教务系统 vs 雨课堂 vs 学习通的脱敏 ID、课程代码格式可能不同 | 单独做 `id_mapping.parquet`（`src/id_mapping.py`），统一成项目内部字符串前缀 ID；**这是 T1 第一件事**，后续所有脚本依赖 |
| 跨系统 | 时间戳格式不统一：教务可能是 `2024-09-01`，雨课堂是 ISO8601，学习通是 Unix 毫秒 | 统一转成 `datetime` 类型 + 用校历表换算成 `week` |
| 雨课堂出勤日志 | 同一学生+课次可能有重复签到（手动补签/网络重试） | 保留最早一次，或标记补签；在质量报告中记录补签比例 |
| 雨课堂出勤日志 | 请假是否算"有效出勤"无统一口径 | 和辅导员确认，在 `schema.yaml` 中固化；**建议分三档**：`attended`（到课）/`attended_leave`（请假）/`absent`（缺勤） |
| 雨课堂出勤日志 | 迟到/早退分钟可能缺省或异常大（>60 分钟） | 缺失按 0 处理，异常大值截断为 30 分钟或单独成一类 |
| 学习通 | 视频观看时长可能 > 视频总时长（快进/多遍） | 截断为 1× 视频时长，另派生 `watch_ratio = 实际时长 / 总时长` |
| 雨课堂随堂小测 | 教师打的知识点标签覆盖率可能不足（部分题未打） | 覆盖率低于 80% 时 T4 知识点映射表要标注，DKT 序列中未标注的题单独标记 `kp_label_missing=1` |
| 考核成绩表 | 补考/缓考学生有多条记录 | 区分 `attempt_index`（第几次考核），DKT 序列用首次考核；标签用最终成绩 |
| 选课注册表 | 撤课/退课学生无成绩记录 | 退课/撤课时间作为 DeepSurv 的事件时间；**必须纳入正例**（见 §4.4） |
| 全局 | 行为日志量极大（全校 2 学年 × 雨课堂/学习通日志，可能 > 1000 万行） | 全程用 `category` dtype / 分块读取 / `parquet` 存中间结果；杜绝 `.iterrows()` |

### 4.3 清洗代码骨架

`src/data_pipeline/02_clean.py`：

```python
from pathlib import Path
import pandas as pd

RAW = Path("data/raw")
INTERIM = Path("data/interim")
INTERIM.mkdir(parents=True, exist_ok=True)

# ── 0. 先加载跨系统 ID 映射（T1 第一件事） ──
def load_id_mapping() -> dict:
    """返回 {source: {raw_id: unified_id}}，source ∈ [stu, course, kp, site]"""
    ...

# ── 1. 原始表加载 ──
def load_raw():
    id_map = load_id_mapping()

    # 学籍表（教务系统）
    stu_info = pd.read_csv(RAW / "student_info.csv")

    # 选课注册表
    reg = pd.read_csv(RAW / "registration.csv")

    # 考核项配置（教务 + 学习平台合并）
    asm_cfg = pd.read_csv(RAW / "assessment_config.csv")

    # 学生考核成绩
    asm_stu = pd.read_csv(RAW / "student_assessment.csv")

    # 校历（开学日作基准）
    calendar = pd.read_csv(RAW / "academic_calendar.csv")

    # 学习平台完整日志（雨课堂 + 学习通合并）—— 大表，降 dtype
    platform_log = pd.read_csv(
        RAW / "platform_behavior_log.csv",
        dtype={
            "student_id": "category", "course_code": "category",
            "resource_id": "category", "resource_type": "category",
        },
        parse_dates=["timestamp"],
    )

    # 随堂小测逐题答题（雨课堂）
    quiz_item = pd.read_csv(
        RAW / "quiz_item_responses.csv",
        dtype={"student_id": "category", "kp_id": "category"},
    )

    return locals() | {"_id_map": id_map}

# ── 2. 统一 ID + 清洗 ──
def clean(stu_info, reg, asm_cfg, asm_stu, calendar, platform_log, quiz_item, _id_map):
    # 统一成项目内部字符串前缀 ID
    stu_info["stu_id"]     = stu_info["raw_stu_id"].map(_id_map["stu"])
    stu_info["course_id"]  = stu_info["raw_course_code"].map(_id_map["course"])
    reg["stu_id"]          = reg["raw_stu_id"].map(_id_map["stu"])
    platform_log["stu_id"] = platform_log["raw_stu_id"].map(_id_map["stu"])
    platform_log["course_id"] = platform_log["raw_course_code"].map(_id_map["course"])
    ...

    # 出勤状态分三档
    platform_log["attendance_status"] = platform_log["attendance"].map({
        "到课": "attended", "正常": "attended",
        "请假": "attended_leave",
        "缺勤": "absent", "未到": "absent", "缺勤无原因": "absent",
    }).fillna("unknown")

    # 同一学生+课次+日期，迟到分钟取最早一次
    platform_log = (
        platform_log.sort_values("timestamp")
        .drop_duplicates(subset=["stu_id", "course_id", "date"], keep="first")
    )

    # 校历换算 week：date - semester_start → 天数 → 整除 7
    ...

    return {
        "student_info": stu_info,
        "registration": reg,
        "assessment_config": asm_cfg,
        "student_assessment": asm_stu,
        "platform_log": platform_log,
        "quiz_item": quiz_item,
        "id_mapping": pd.DataFrame(...),
    }

def save(tables):
    for name, df in tables.items():
        df.to_parquet(INTERIM / f"{name}.parquet", index=False)

if __name__ == "__main__":
    save(clean(**load_raw()))
```

**引用完整性校验**（放进 `tests/test_data_integrity.py`）：

```python
import pandas as pd

def test_referential_integrity():
    info = pd.read_parquet("data/interim/student_info.parquet")
    reg  = pd.read_parquet("data/interim/registration.parquet")
    asm  = pd.read_parquet("data/interim/student_assessment.parquet")

    stu_crs_keys = set(zip(info.stu_id, info.course_id))
    reg_keys     = set(zip(reg.stu_id, reg.course_id))
    # 注册表里的学生×课程必须都在学籍表中
    assert reg_keys <= stu_crs_keys

    # 有成绩记录的考核项必须在 assessment_config 表中存在
    cfg = pd.read_parquet("data/interim/assessment_config.parquet")
    assert set(asm.assessment_id) <= set(cfg.assessment_id)

    # 行为日志引用的 student / course 必须在学籍表中
    log = pd.read_parquet("data/interim/platform_log.parquet")
    log_keys = set(zip(log.stu_id, log.course_id))
    # 允许日志中有少量孤儿记录（数据清洗不完全），比例 < 5% 即可
    assert len(log_keys - stu_crs_keys) / len(log_keys) < 0.05

def test_score_range():
    asm = pd.read_parquet("data/interim/student_assessment.parquet")
    assert asm.score.dropna().between(0, 100).all()

def test_no_future_leak_in_static():
    """静态特征不能含任何课程结束后才知道的信息"""
    info = pd.read_parquet("data/interim/student_info.parquet")
    forbidden = ["final_grade", "gpa_after", "retaken"]
    for col in forbidden:
        assert col not in info.columns, f"静态特征不应含 {col}"
```

### 4.4 统一标签口径（**需要全组确认的第一件事**）

本校 `final_result` → 建模标签建议这样定，并在 `configs/schema.yaml` 固化：

```yaml
label:
  risk_binary:          # HAN / TFT 主任务
    rule: "final_result in ['不合格', '缺考', '退学', '休学', '学业警示'] => 1"
    note: "挂科、缺考、退学、休学都视为风险事件；补考后仍不合格的也算 1"
  risk_level:           # 前端低/中/高风险分级（阶段二用模型概率再细分）
    0: "优秀/良好/合格"
    1: "不合格/缺考"
    2: "退学/休学/学业警示"
  deepsurv_event:       # DeepSurv 生存分析事件定义
    rule: "(event=1, time=首次风险信号周)"
    risk_signals:       # 任一信号出现时触发事件
      - "退学/休学日期"
      - "首次考核不及格周次"
      - "连续 2 周出勤率 < 50%"
```

注意：**退学/休学学生必须纳入正例**——且时序建模时把退课日之后的行为特征 mask 掉（人已离校，数据缺失≠没学）。正例比例取决于本校挂科率，若过低（< 10%）则阶段二需要样本不平衡处理（class weight / 欠采样 / focal loss）。

## 5. 任务二：异质图 Schema 设计与构建（T2）

### 5.1 先想清楚图要回答什么问题

阶段二的 HAN 和阶段三的 GNNExplainer 要回答：

- 先修课/前置知识薄弱如何**沿边传导**到当前课程风险？
- 高风险学生的关键关联子图里，哪些课程、知识点、出勤行为"贡献"了风险？
- **出勤达标能否沿同班同侪边传递**（出勤率高的班级，同班学生整体成绩更好）？

所以 Schema 设计的优先级是：**语义清晰 > 边类型丰富 > 节点特征复杂**。

### 5.2 节点类型（5 类，OULAD 版本新增 `class_session`）

| 节点类型 | 标识 | 来源表 | ID 规范 | 节点特征 |
|---|---|---|---|---|
| 学生 | `student` | 学籍表+注册表 | `stu_{统一学号}` | 性别、专业、年级、入学前学历、入学成绩、既往修读次数、注册学分、残疾标记 |
| 课程开课 | `course` | 课程目录+选课 | `crs_{课程代码}_{学期}` | 课程性质、学分、学期、课程长度 |
| **课次** | `class_session` | 行为日志中的签到记录 | `cs_{课程代码}_{星期几}_{周次}` | 授课日期、周次、班级、授课教师（若有） |
| 知识点 | `knowledge_point` | T4 映射表 | `kp_{课程代码}_{编号}` | 所属课程、建议周次、难度（历史错误率） |
| 学习资源 | `resource` | 行为日志 | `res_{资源ID}` | `resource_type`（课件/视频/测验/讨论区）one-hot、所属课程 |

> OULAD 版本没有 `class_session` 节点，本校数据新增后可以表达"学生是否上了第 5 周周三的高数课"这种精确行为。

### 5.3 边类型（7+ 类，含本校新增的出勤边）

| 关系 | 三元组 `(src, rel, dst)` | 来源 | 边属性 |
|---|---|---|---|
| 选课 | `(student, enrolled_in, course)` | 注册表 | 注册日期、是否退课、退课日期 |
| **出勤** | `(student, attended, class_session)` | 行为日志签到 | 出勤状态（attended/attended_leave/absent）、迟到分钟、签到时间 |
| **同班同侪** | `(student, attended_with, student)` | 同上（同 `class_session` 的学生两两连边） | 该课次的出勤率、班级 |
| 成绩关联 | `(student, scored_on, knowledge_point)` | 考核成绩表 + 知识点映射 | 分数、迟交天数、是否补考 |
| 学习交互 | `(student, interacts_with, resource)` | 行为日志 | 日期、总点击、视频观看比 |
| 课程包含知识点 | `(course, has_kt, knowledge_point)` | T4 映射表 | 建议周次 |
| 知识点依赖 | `(knowledge_point, prereq_of, knowledge_point)` | T4 依赖链 | 依赖强度、来源（manual/rule） |
| 资源服务知识点 | `(resource, supports, knowledge_point)` | T4（按周+课程挂接） | — |
| **课程先修** | `(course, prereq, course)` | **本校独有（培养方案）** | — |

> ⚠️ 对比 OULAD 版本：新增了 `class_session` 节点、`attended`/`attended_with` 边和 `course prereq course` 边；删掉了宿舍同侪边（暂不实现，见 §11）。

### 5.4 元路径（给阶段二 HAN 预备）

- `student—enrolled_in→course←enrolled_in—student`：同课程同学（同侪效应）；
- **`student—attended→class_session←attended—student`**：同班同侪（出勤行为的传递性，**本校版核心元路径**）；
- `student—scored_on→kp←prereq_of—kp`：知识漏洞传导路径（**平台核心卖点**）；
- `student—interacts_with→resource—supports→kp`：学习行为→知识点的投入证据；
- `student—enrolled_in→course—has_kt→kp`：学生与知识点的间接关联（冷启动学生用）。

> 暂缓的元路径（见 §11）：宿舍同侪、跨模块知识点依赖（暂只做课程内）。

### 5.5 本校数据的优势：先修关系和随堂小测知识点标签

这两部分是 OULAD 没有的，**直接提升 HAN 知识传导和 DKT 序列粒度的质量**：

1. **课程先修关系**来自教务处培养方案，不是数据驱动的 proxy——HAN 的 `(course, prereq, course)` 边有真实业务含义，GNNExplainer 解释时可以说"你的先修课高数成绩不足，导致当前线性代数风险"而不是"数据显示两门课相关"。
2. **随堂小测逐题知识点标签**由授课教师在雨课堂出题时填写——DKT 的答题序列直接升级为**小题级精确序列**，不需要从考核项反推知识点（OULAD 版是近似，本校版是精确）。

### 5.6 三种存储格式（一次构建，三处使用）

| 格式 | 文件 | 谁用 |
|---|---|---|
| 边列表 CSV（节点表 + 每种关系一个 edge csv） | `data/processed/graph/*.csv` | 后端 ETL 入 PostgreSQL/Neo4j；人工核查 |
| NetworkX `node_link_json` | `graph_nx.json` | 快速校验、阶段三 GNNExplainer 子图裁剪 |
| PyG `HeteroData`（`.pt`） | `hetero_data.pt` | 阶段二 HAN 直接加载 |

构建代码骨架 `src/data_pipeline/05_build_graph.py`：

```python
import pandas as pd
import networkx as nx
import torch
from torch_geometric.data import HeteroData

P = "data/processed"

def build_heterodata() -> HeteroData:
    # 加载节点表（由 T1 + T4 产出）
    stu      = pd.read_parquet(f"{P}/dim_student.parquet")
    crs      = pd.read_parquet(f"{P}/dim_course.parquet")
    cs       = pd.read_parquet(f"{P}/dim_class_session.parquet")   # 本校新增
    kp       = pd.read_parquet(f"{P}/dim_knowledge_point.parquet")
    res      = pd.read_parquet(f"{P}/dim_resource.parquet")

    # 字符串 ID -> 连续整型索引的映射表（务必同时落盘，供解释器反查）
    sid = {s: i for i, s in enumerate(stu.node_id)}
    cid = {c: i for i, c in enumerate(crs.node_id)}
    csid= {c: i for i, c in enumerate(cs.node_id)}
    kid = {k: i for i, k in enumerate(kp.node_id)}
    rid = {r: i for i, r in enumerate(res.node_id)}

    data = HeteroData()
    data["student"].x          = torch.tensor(stu.feature_vec.tolist(), dtype=torch.float)
    data["course"].x           = torch.tensor(crs.feature_vec.tolist(), dtype=torch.float)
    data["class_session"].x    = torch.tensor(cs.feature_vec.tolist(),  dtype=torch.float)
    data["knowledge_point"].x  = torch.tensor(kp.feature_vec.tolist(), dtype=torch.float)
    data["resource"].x         = torch.tensor(res.feature_vec.tolist(), dtype=torch.float)

    def edge_index(df, src_col, dst_col, src_map, dst_map):
        src = df[src_col].map(src_map).to_numpy()
        dst = df[dst_col].map(dst_map).to_numpy()
        return torch.tensor([src, dst], dtype=torch.long)

    e_enroll = pd.read_parquet(f"{P}/edge_enrolled_in.parquet")
    data["student", "enrolled_in", "course"].edge_index = edge_index(
        e_enroll, "src", "dst", sid, cid)

    # 本校新增：出勤边
    e_attend = pd.read_parquet(f"{P}/edge_attended.parquet")
    data["student", "attended", "class_session"].edge_index = edge_index(
        e_attend, "src", "dst", sid, csid)
    data["student", "attended", "class_session"].edge_attr = torch.tensor(
        pd.get_dummies(e_attend["attendance_status"]).to_numpy().astype("float32"))

    # 同班同侪边（可选，量大时采样构建）
    # ...

    e_score = pd.read_parquet(f"{P}/edge_scored_on.parquet")
    data["student", "scored_on", "knowledge_point"].edge_index = edge_index(
        e_score, "src", "dst", sid, kid)
    data["student", "scored_on", "knowledge_point"].edge_attr = torch.tensor(
        e_score[["score", "days_late"]].fillna(0).to_numpy(), dtype=torch.float)

    # interacts_with / has_kt / prereq_of / supports / course_prereq 同理……
    return data

def validate(G: nx.MultiDiGraph):
    # 1) 知识点依赖边不允许成环（依赖链必须是 DAG）
    kp_sub = G.subgraph([n for n, d in G.nodes(data=True) if d["type"] == "knowledge_point"])
    kp_dag = nx.DiGraph(kp_sub)
    assert nx.is_directed_acyclic_graph(kp_dag), "知识点依赖子图存在环，修复映射表"
    # 2) 课程先修边不允许成环
    crs_sub = G.subgraph([n for n, d in G.nodes(data=True) if d["type"] == "course"])
    crs_dag = nx.DiGraph(crs_sub)
    assert nx.is_directed_acyclic_graph(crs_dag), "课程先修子图存在环"
    # 3) 孤立节点比例（学生无任何边属正常，课程无知识点边则 T4 漏映射）
    # 4) 每条边两端节点必须存在
```

**图校验清单**：① 每条边两端节点存在；② 知识点依赖子图 + 课程先修子图都是 DAG；③ 孤立节点比例统计；④ 每种关系的边数、度数分布直方图入质量报告；⑤ 整型索引↔原始 ID 映射表落盘（阶段三解释器要靠它反查）。

## 6. 任务三：时序特征提取（T3）

### 6.1 时间轴定义

- 用校历表换算：学期开学日 = week 0；每 7 天为一周，`week = (date - semester_start).days // 7`；
- 一条时序样本 = 一个 `(学生, 课程开课)`；每个时间步 = 一周；
- 期末成绩只在课程结束后可知，**严禁出现在任何历史时间步特征中**。

### 6.2 三类特征（TFT 标准输入格式，**本校版 30+ 维时变特征**）

1. **静态特征（static）**：学籍表——性别、专业、年级、入学前学历、入学成绩、既往修读次数、注册学分、残疾标记；
2. **观测到时变特征（observed）**：
   - **出勤（本校核心）**：周出勤率（attended / 应到课次）、迟到次数、早退次数、请假次数、连续缺勤周次、`attendance_status` 三档计数；
   - **学习平台交互**：周 PPT 总点击、按资源类型拆分的点击量（课件/视频/测验/讨论区）、活跃天数、访问资源数、视频观看比；
   - **随堂小测**：本周随堂小测平均分、累计正确率、知识点掌握覆盖数、未标注知识点的答题次数；
3. **已知未来时变特征（known future）**：每周是否有考核截止、考核类型（期中/期末/作业）、考核权重、**课程表上的法定授课周次**（和出勤数据天然对齐，课程表开学即确定）。

### 6.3 周特征表 schema（长表，便于切片）

`data/processed/weekly_features.parquet`：

| 列 | 说明 |
|---|---|
| `student_course_id` | 学生×课程开课主键 |
| `week` | 0..课程长度周数 |
| **`attendance_rate`** | 本周出勤率（核心） |
| **`late_count` / `leave_count` / `absent_count`** | 迟到/请假/缺勤次数 |
| `consecutive_absent_weeks` | 连续缺勤周次（到本周为止） |

`src/data_pipeline/03_weekly_features.py`：

```python
import pandas as pd

INTERIM, OUT = "data/interim", "data/processed"

def build_weekly_features() -> pd.DataFrame:
    log  = pd.read_parquet(f"{INTERIM}/platform_log.parquet")
    quiz = pd.read_parquet(f"{INTERIM}/quiz_item.parquet")
    asm  = pd.read_parquet(f"{INTERIM}/student_assessment.parquet")

    # ── 出勤按周聚合 ──
    # 先在 groupby 前派生 flag 列（避免在 agg 里访问 Series 内部字段）
    log["late_flag"] = ((log["attendance_status"] == "attended")
                        & (log.get("late_minutes", pd.Series(0, index=log.index)) > 0)
                       ).astype("int8")
    attend = (
        log.groupby(["stu_id", "course_id", "week"], observed=True)
        .agg(
            sessions_total=("class_session_id", "count"),
            sessions_attended=("attendance_status",
                               lambda x: (x == "attended").sum()),
            late_count=("late_flag", "sum"),
            leave_count=("attendance_status", lambda x: (x == "attended_leave").sum()),
            absent_count=("attendance_status", lambda x: (x == "absent").sum()),
        )
        .reset_index()
    )
    attend["attendance_rate"] = (
        attend["sessions_attended"] / attend["sessions_total"].clip(lower=1)
    ).astype("float32")

    # ── 平台行为按周聚合（ppt/video/quiz/forum 拆分） ──
    activity = (
        log.groupby(["stu_id", "course_id", "week", "resource_type"], observed=True)
        .size().unstack("resource_type", fill_value=0)
        .add_prefix("clicks_").reset_index()
    )

    # ── 随堂小测按周聚合 ──
    quiz["week"] = quiz["timestamp"].dt.dayofweek   # 或通过关联课次
    quiz_weekly = (
        quiz.groupby(["stu_id", "course_id", "week"], observed=True)
        .agg(quiz_avg_score=("score", "mean"),
             quiz_count=("item_id", "count")).reset_index()
    )

    # ── 合并三块 + 补齐完整周 + 成绩挂接 ──
    weekly = attend.merge(activity, on=["stu_id", "course_id", "week"], how="outer") \
                   .merge(quiz_weekly, on=["stu_id", "course_id", "week"], how="outer")

    # 补齐 0..max_week 完整网格
    weekly = pad_full_weeks(weekly)

    # 挂接累计统计、连续缺勤周次、成绩、标签
    weekly = enrich_with_cumsum_and_label(weekly, asm, ...)
    return weekly

    成绩/考核列保留 NaN（=本周无考核）。"""
```

### 6.5 防泄漏 checklist（TFT/DeepSurv 上线效果全靠它）

- [ ] 任何周 t 的特征只用 `week <= t` 的数据；
- [ ] `final_result`、退学/休学日期只能作为标签/事件时间，不能进特征；
- [ ] 静态特征只能含入学前已知的信息（入学成绩、性别、专业等），不能含入学后累积的 GPA/挂科记录；
- [ ] 阶段二验证预警提前量时，需要能在任意周次截断生成特征快照——周表设计要天然支持 `week <= t` 切片；
- [ ] DeepSurv 事件时间按 §4.4 定义写入 `schema.yaml`；
- [ ] **跨班次泄露**：同一学生历史班次成绩是合法强特征，但按学生随机切分训练/测试集会造成跨班次泄露——阶段二切分要按脱敏学号分组切分，阶段一就在学籍表预留 `split_group` 列（= 脱敏学号）。

## 7. 任务四：知识点体系与 DKT 逐题序列（T4）

### 7.1 本校版与 OULAD 版的关键区别

| 方面 | OULAD 版 | 本校版 |
|---|---|---|
| 知识点来源 | 不存在原生标签，靠规则+人工字典反推 | 随堂小测逐题**自带教师打的知识点标签**，课程大纲有培养方案 |
| 知识点依赖 | 规则排序 + 人工字典 | **培养方案给出的先修关系 + 教师确认的知识链条** |
| DKT 序列粒度 | "考核项×知识点"近似（1 个 TMA 拆成 N 个 KP 事件） | **逐题精确**（每道小测/作业题一个事件） |
| 序列构造 | 按考核周拆分，同一 TMA 内多题共享同一个得分 | 每道题独立一条事件，含知识点 ID、题目得分、正确/错误 |

### 7.2 执行步骤

1. **提取随堂小测逐题记录**：从 `quiz_item.parquet` 读取 `(stu_id, course_id, item_id, kp_id, score, max_score, timestamp)`，这就是 DKT 的核心数据源；
2. **补齐非考核周的学习资源映射**：对没有随堂小测的周（或部分题未打知识点标签），按课程大纲将 PPT/视频/讨论区资源挂到对应知识点——这部分延续 OULAD 版的规则挂接逻辑；
3. **人工建典**：为开设的课程各整理一份知识点字典（每门课 8–15 个 KP，规模可控），字段见 7.3；
4. **依赖成链**：按培养方案给出的先修关系 + 知识点周次排序形成主链；未在先修表中的课程内部知识点，按授课顺序人工补边；每条边标注来源：`manual`（培养方案/教师）/`rule`（按周次）；
5. **覆盖率核对**：随堂小测的知识点标签覆盖率 ≥80% 即可接受，低于此数的课程需要额外做人工补充。

### 7.4 构造 DKT 逐题答题序列

```text

按 week 排序；同一周内多道题按 timestamp 顺序
```

### 9.2 给前端提前对齐的子图 JSON 格式（阶段三才用，但 Schema 现在定死成本最低）

```json
{
  "student_id": "stu_a1b2c3",
  "nodes": [
    {"id": "kp_AAA_03", "type": "knowledge_point", "name": "导数概念",
     "contribution": 0.42},
    {"id": "cs_AAA_Wed_wk5", "type": "class_session", "name": "周三第5周课",
     "contribution": 0.28}
  ],
  "edges": [
    {"source": "stu_a1b2c3", "target": "cs_AAA_Wed_wk5",
     "relation": "attended", "contribution": 0.28},
    {"source": "stu_a1b2c3", "target": "kp_AAA_03",
     "relation": "scored_on", "contribution": 0.42}
  ],
  "summary": "第3周起出勤率降至 40%，导数知识点随堂小测正确率持续低于 50% → 风险上升"

```

前端可据此提前定 AntV G6 的节点配色（按 `type`）与边粗细（按 `contribution`）规范，**`attended` 边用虚线区分出勤 vs 缺勤**。

### 9.3 给前端提前对齐的 T3 产出字段

- `attendance_rate` 是核心特征，前端预警看板可以直接作为"学习投入度"的可视化指标；
- `consecutive_absent_weeks` ≥ 2 可作为低风险到中风险的自动升级信号。

## 13. 风险与踩坑提醒

1. **数据合规先于技术**：开学前先跑合规审批，别等 D1 才发现拿不到原始导出；导出格式（CSV/JSON）提前和管理员确认；
2. **跨系统 ID 打通是 T1 的关键路径**，卡在 D2 的话后面全部推迟——优先级最高；
3. **不要等知识点完美才动图**：随堂小测自带标签的题先跑通，未标注的题后续迭代补，阶段二训练会反过来暴露映射问题；
4. **出勤率阈值不是 80%**：每个学生、每门课的合理出勤水平不同，因果分析时要分课程/分班级做对照，不能一个统一阈值；
5. **退学/休学学生的时序尾部**：退课后无行为是结构性缺失，特征工程要区分"没学"和"数据缺失"，DeepSurv 的事件时间用退课日而非最后一次行为日；
6. **行为日志量极大**：全程用分类 dtype / 分块，杜绝 `.iterrows()`；聚合一次存 Parquet，后续都读 interim；
7. **随机性与可复现**：所有规则型构建（周划分、ID 生成）写成确定性代码；需要人工判断的内容只进映射表 CSV，不写死在代码里；
8. **多班次泄露**：按脱敏学号分组切分训练/测试集，阶段一预留 `split_group` 列；
9. **随堂小测标注覆盖率不足**：部分题未打知识点标签时，DKT 序列里保留这些题但标记 `kp_label_missing=1`，不要丢掉——题目本身有信息量；
10. **班级人数差异**：同班同侪边在大班级可能产生大量冗余边，可以按出勤率高于/低于均值筛选或采样构建，不必全连。
