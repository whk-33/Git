## 0. Mock 数据策略（**写代码前先确认这一节**）

### 0.1 为什么用 mock 数据

- **不等数据合规审批**，拿到真实数据可能要 2–4 周，期间算法侧可以把整个 pipeline、图构建、时序特征、DKT 序列全部跑通；
- **Schema 验证**：写 mock 生成器本身就是对 8 张表的粒度、字段、约束的最佳检验——生成脚本写错了，说明你对 Schema 理解还有 gap；
- **前后端联调**：mock 数据无隐私问题，可以直接进 git，队友 clone 下来就能跑；
- **可重复可复现**：用固定 seed 生成，队友跑出来和你一模一样；
- **故意注入可学习信号**：让 pipeline 验证阶段就能看到模型效果，而不是"跑通但什么都学不到"。

**二期替换真实数据**：只需改数据源适配层（读取路径 + 字段映射 + 清洗规则），pipeline 通用层逻辑（§4–§7）一字不动。

### 0.2 Mock 数据规模

| 参数 | 值 | 理由 |
|---|---|---|
| 学生数 | **200** | 足够训练（正例 ~25% → 50 人），生成不慢 |
| 课程 | **5 门**（如：AAA 高等数学、BBB 线性代数、CCC 大学英语、DDD Python、EEE 数据结构） | 覆盖不同类型，先修链清晰（AAA→BBB→EEE） |
| 学期 | **2**（2024F + 2025S） | 学生跨学期有历史可复用 |
| 总学生×课程 | 200 学生 × 5 课 × 2 学期 × 80% 选课率 = **~1600** 条学籍 | |
| 行为日志 | 每学生每课 ~200 条点击 → **~32 万行** | PyG 异构图 + TFT 时序特征能扛住 |
| 随堂小测逐题 | 每课每学期 8 次 × 10 题 → **8000** 题次 | DKT 逐题序列够用 |

### 0.3 Mock 数据分布（故意注入可学习信号）

| 分布/信号 | 怎么造 | 目的 |
|---|---|---|
| 正例比例 | ~25%（50 学生）：挂科 35 + 缺考 5 + 退学 5 + 休学 5 | 健康比例，不需 focal loss |
| 出勤率分布 | 负例学生均值 85%，正例学生均值 45%，标准差 15% | **TFT / DoWhy 因果分析核心信号** |
| PPT 点击量 | 出勤率 > 80% 的学生 → 点击量高出勤率 < 50% 的 2 倍 | 时变特征相关 |
| 随堂小测 | 正例学生正确率序列**从第 4 周开始明显下滑**（先微涨→平台→跳崖）；负例学生稳定 | DKT 难度梯度信号 |
| 先修关联 | AAA（高数）期末 < 60 → BBB（线代）挂科概率 70%；AAA ≥ 75 → BBB 挂科 < 10% | HAN 知识传导边信号 |
| 同班同侪 | 班级整体出勤率均值 ± 10%，同班学生成绩分布一致 | 同班同侪元路径信号 |
| 退学/休学 | 5 个学生：行为日志在退课周直接截断 + 事件时间写入 | DeepSurv 生存分析事件 |
| 补考学生 | 10 个：首次考核成绩低、第二次补考过了 → `attempt_index=2` | 区分补考 vs 挂科 |
| 未打知识点标签的随堂小测题 | 15% 的题 kp_id 设为 NULL，加 `kp_label_missing=1` | DKT 边界 case |
| 迟到/请假 | 每学生每学期 0–3 次请假（合法）、缺勤正例学生迟到 4+ 次 | 出勤三档口径 |
| 时间戳格式不统一 | mock 故意生成多种格式混入（ISO8601 / Unix 毫秒 / 纯日期） | 验证 §4.3 清洗脚本的时间对齐逻辑 |
| 跨系统 ID 不统一 | mock 故意让学籍表用 `stu_` 前缀、行为日志用纯数字 ID、雨课堂用 UUID 格式 | 验证 ID 映射脚本 |
| 行为日志噪声 | 5% 的行为是"无效"（比如同一天同一课次重复签到、时间戳越界） | 验证聚合去重逻辑 |

## 1. 这份文档解决什么问题

阶段一算法侧任务，拆成 T0–T4 五步，每步「做什么 → 为什么 → 代码骨架 → 产出 → 验收」：

1. **T0 Mock 数据生成**（前置，先写这个）——故意注入可学习信号，同时制造跨系统 ID 不一致、时间格式混乱等真实世界问题；
2. **T1 Mock pipeline 验证**——清洗 + ID 打通，故意造脏的数据让你验证清洗脚本真能处理脏数据；
3. **T2 异质图 Schema 设计与构建**（含 `class_session` 节点、出勤边、同班同侪元路径）；
4. **T3 按周粒度的时序特征提取**（出勤率 / PPT 交互 / 随堂小测并入时变特征）；
5. **T4 知识点体系与 DKT 逐题序列**（利用随堂小测自带的知识点标签）。

**阶段一的所有产出都是阶段二 4 个模型的输入**，请始终带着下游视角工作：

| 下游模型（阶段二/三） | 依赖你阶段一的什么产出 |
|---|---|
| 异质 GNN（HAN） | 异构图文件（节点、边、元路径）、节点特征、同班同侪元路径 |
| DKT 知识点级预警 | **逐题答题序列**（随堂小测）、知识点映射表 |
| TFT + DeepSurv 时序预警 | 静态特征 + **出勤/PPT 交互/随堂小测并入**的时变特征表、标签时间轴 |
| DoWhy 因果推断 | 干净的宽表——**treatment = 出勤达标率**、混淆变量、结果变量 |
| GNNExplainer（阶段三） | 图 Schema 中节点/边类型语义清晰、ID 稳定、出勤边可解释 |

## 3. 前置准备

### 3.1 先定的几个口径（**写进 `configs/schema.yaml`，mock 生成器用，后面不再争论**）

1. **分析主体是「学生 × 课程开课（学期）」**，不是学生本人；
2. **标签二值化规则**：`status ∈ {不合格, 缺考, 退学, 休学, 学业警示} → y=1`，否则 y=0；

## 4. 任务 T0：Mock 数据生成器（**最先写这个，第 1 天完成**）

### 4.1 为什么最先写 mock 生成器

- 它是对你理解 Schema 的**第一次实战检验**——生成 8 张表 + 注入信号 = 你必须想清楚每张表的粒度、字段、约束、表间引用关系；
- 故意造脏数据（跨系统 ID 不一致、时间格式混乱、无效行为噪声）= 你后面写清洗脚本时已经提前知道脏数据长什么样，不会踩隐形坑；
- 固定 seed = 队友 clone 下来跑出来一模一样；
- mock 数据无隐私，可以进 git，前后端可以直接用来联调。

**故意造脏的 3 个关键设计**（mock 生成器必须做，否则 T1 就没东西可验）：

1. **跨系统 ID 不一致**：
   - `student_info.csv` 的 `stu_id` = 纯数字（`"100001"`）；
   - `registration.csv` 和 `student_assessment.csv` 的 `stu_id` = 纯数字（`"100001"`）但和 student_info 完全同一套——这两张"教务系统"表 ID 一致；

   - `quiz_item_responses.csv` 的 `stu_id` = 纯数字但**偏移 +1000000**（`"1100001"`）——另一套；
   - 这样清洗脚本必须写 `id_mapping` 把四套 ID 全部打通成统一前缀格式。

2. **时间格式混乱**：
   - 部分时间戳用 ISO8601：`"2024-10-12T09:30:00"`；
   - 部分用纯日期：`"2024-10-12"`；
   - 部分用 Unix 毫秒字符串：`"1728711000000"`；
   - 清洗脚本必须能处理三种格式。

3. **噪声**：
   - `platform_log` 里 5% 重复签到（同一学生 + 课次 + 日期）；
   - 3% 迟到分钟 > 60（异常值）；
   - 2% 缺勤却有签到时间（矛盾）；
   - 清洗脚本的 `drop_duplicates` + 截断 + 缺失处理要能覆盖。

    quiz   = pd.read_csv(RAW / "quiz_item_responses.csv")  # 偏移 +1000000
    cal    = pd.read_csv(RAW / "academic_calendar.csv")

def build_id_mapping(info, reg, log, quiz) -> dict:
    """打通四套学生 ID → 统一 stu_ 前缀格式"""
    # info 的 stu_id = 纯数字；reg 的 stu_id = 同一纯数字
    # log 的 stu_id = UUID；quiz 的 stu_id = 纯数字但偏移 +1000000
    unified = {str(x): f"stu_{x}" for x in info.stu_id}
    # 把 quiz 的偏移去掉
    quiz_id_map = {str(int(x) - 1_000_000): v
                   for x, v in unified.items()}
    # log 的 UUID 需要 faker 生成时就记录下"UUID → 纯数字"的映射
    # 所以 mock 生成器应该导出一个 id_crosswalk.csv
    # 这里简化：log 的 stu_id 用另一套 crosswalk
    return unified, quiz_id_map, log_crosswalk

def unify_timestamp(series: pd.Series) -> pd.Series:
    """三种格式统一转 datetime"""
    def parse(x):
        if pd.isna(x):
            return pd.NaT
        s = str(x).strip()
        # Unix 毫秒
        if s.isdigit() and len(s) > 12:
            return pd.to_datetime(int(s), unit="ms")
        # ISO / 纯日期
        return pd.to_datetime(s, errors="coerce")
    return series.map(parse)

def clean(**raw):
    # 1. ID 打通
    unified, quiz_map, log_map = build_id_mapping(...)

    info["stu_id"] = info["stu_id"].astype(str).map(unified)
    reg["stu_id"]  = reg["stu_id"].astype(str).map(unified)
    asm["stu_id"]  = asm["stu_id"].astype(str).map(unified)
    log["stu_id"]  = log["stu_id"].map(log_map)          # UUID → stu_ 前缀
    quiz["stu_id"] = quiz["stu_id"].astype(str).map(quiz_map)  # 偏移 → stu_ 前缀

    # 2. 时间戳统一
    log["timestamp"]  = unify_timestamp(log["timestamp"])
    asm["submit_time"] = unify_timestamp(asm["submit_time"])
    quiz["timestamp"]  = unify_timestamp(quiz["timestamp"])

    # 3. 去重 + 截断 + 矛盾处理
    log = (log.sort_values("timestamp")
              .drop_duplicates(subset=["stu_id", "course_code", "class_session_id", "date"],
                                keep="first"))
    log["late_minutes"] = log["late_minutes"].clip(upper=30)
    # 缺勤却有签到时间 → 状态改为 unknown
    log.loc[(log["attendance_status"] == "absent") & (log["timestamp"].notna()),
            "attendance_status"] = "unknown"

    # 4. 校历换算 week
    cal_map = {r.semester: pd.Timestamp(r.start_date) for r in cal.itertuples()}
    log["week"] = ((log["timestamp"].dt.normalize()
                    - log["semester"].map(cal_map)).dt.days // 7).clip(lower=0, upper=16)

    # 5. 退学学生 drop_date 之后的记录剔除
    dropped = reg[reg["drop_date"].notna()][["stu_id", "course_code", "semester", "drop_date"]]
    # …… join + filter

    return {
        "student_info": info, "registration": reg,
        "assessment_config": asm_cfg, "student_assessment": asm,
        "platform_log": log, "quiz_item": quiz,
        "final_result": final_result, "calendar": cal,
        "id_mapping": pd.DataFrame(...),
    }

def save(tables):

        df.to_parquet(INTERIM / f"{name}.parquet", index=False)

## 11. 风险提醒（mock 版新增 + 保留通用）

**mock 特有的**

1. **mock 信号可能过于理想化**：真实数据里"出勤率低 → 挂科"可能没这么干净，模型上线前一定要用真实数据重训并调整阈值；
2. **mock 规模太小**：HAN 在 5 节点小图上能跑通但不能说明大规模表现，真实数据到位后再评估图大小和 GPU 需求；
3. **不要为了让 pytest 过而削信号**：`test_signal_present` 的正例出勤率 < 50% 是设计要求，如果 mock 生成器造不出来，说明信号注入有问题而不是测试要求高；

**通用保留**

4. **退学/休学学生时序尾部是结构性缺失**，特征工程要区分"没学"和"数据缺失"；
5. **行为日志聚合一次存 Parquet**，杜绝 `.iterrows()`；
6. **按脱敏学号分组切分训练/测试**，阶段一预留 `split_group` 列；
7. **同班同侪边在大班级可采样**，不必全连；
8. **缺勤周次 > 6 周的学生**应标记为"结构缺失"（可能退学或换课），不要丢进负例。
